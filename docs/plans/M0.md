# M0 — Skeleton and performance harness

## Files
- `brand.json`, `scripts/apply-brand.mjs` → `src-tauri/src/brand.rs`, `src/brand.ts`, `tauri.conf.json`, `package.json`, `index.html`
- `src-tauri/` Tauri 2 app (`lib.rs`, `main.rs`, `db/`), `src/` React + Vite + Tailwind
- `scripts/perf.mjs`, `.github/workflows/ci.yml` (build matrix + macOS arm64 perf job)
- `AGENTS.md`, `docs/DECISIONS.md`, `docs/perf.md`

## Interfaces
- `db::Db` — owns one SQLite connection (WAL). Reads are synchronous under a mutex; writes that happen often (events, metrics) go through `db::Writer`, a background thread that batches (flush every 250 ms or 200 rows).
- Migrations: `PRAGMA user_version` plus an ordered list of SQL scripts.

## Tests
- `db` unit tests: migrations are idempotent, the batch writer flushes on count and on time.
- apply-brand: running it twice is a no-op; a changed `productName` flows into `tauri.conf.json` and `brand.ts`.

## Budget impact
- Release profile: LTO, `opt-level = "s"`, strip, `panic = "abort"`. Expect a bundle of ~8–12 MB.
- No timers at idle; the writer thread blocks on its channel with a timeout only while rows are pending.
